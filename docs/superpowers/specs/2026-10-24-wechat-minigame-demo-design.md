# 熟人局升级 · 微信小游戏 Demo 迁移设计

## 目标与范围

将现有普通小程序交互原型迁移为可由微信开发者工具以小游戏模式启动的本地 Demo，供查看界面和体验流程。名称统一为“熟人局升级”。这次不实现完整升级规则、真实联机、真实语音、登录或发布审核。

## 方案取舍

- 原生 Canvas（用户已选择）：无需引擎和构建依赖，适合当前轻量牌桌原型；界面布局、触摸和绘制由代码实现。
- Cocos Creator（不采用）：有利于复杂动画和资源管理，但增加工具链与迁移成本。

## 实现边界

- 新增独立小游戏目录，提供 game.js、game.json、Canvas 绘制及触摸入口；根项目配置切换到小游戏及对应源码目录。
- 保留 miniprogram 目录，不覆盖旧原型；小游戏复用现有纯规则模块，不修改规则定义。
- 使用竖屏、自适应尺寸与高清屏缩放，并避开顶部安全区域。
- 保留房间、叫主、三轮脚本出牌、结算、互动卡、继续下一局的流程。
- 玩家为本地模拟，出牌与分数为脚本数据；界面常驻标注“本地演示”，语音开关明确为模拟，不申请麦克风权限。
- 互动卡只做本地可见反馈，不宣称真实跨玩家同步或语音禁言。每次结算最多使用一张卡，再来一局重置演示状态。
- 本次不添加引擎、服务器、外部服务、素材下载或额外玩法。Canvas 布局与配色由实现者参考原有深绿金色界面决定。

## 验收

1. 根配置为小游戏类型，源码目录存在 game.js 和合法 game.json，不再寻找 miniprogram/game.json。
2. 在模拟 Canvas / 微信 API 环境下验证启动、触摸命中及完整演示流程，验证重复点击不重复结算或使用互动卡。
3. 现有规则测试继续通过，新增演示状态测试。
4. README 写清导入目录、小游戏 AppID 要求、体验流程及未实现能力。
5. 微信开发者工具及真机表现需实际预览确认；若当前环境无法启动工具，交付时明确说明，不将模拟测试表述为真机验证。
