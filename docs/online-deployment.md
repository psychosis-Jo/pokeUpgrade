# 四人好友联机：部署与验收

好友房入口已接入小游戏大厅，人机练习继续独立运行。好友房需要部署登录云函数、云数据库和云托管服务；仅导入项目不会自动开通这些资源。

## 1. 本地验证

需要 Node.js 22 和 npm。在项目根目录执行：

```sh
npm ci
npm test
```

40项测试包括原有30项，以及客户端、会话、并发抢座/叫主、暗牌隔离、非法操作、超时投票/托管、持久化恢复、结算与互动幂等测试。四个真实 WebSocket 测试客户端可以打完整局，但不等于四个微信真机账号验证。

本地服务启动（该口令仅供本地测试，禁止用于云端）：

```sh
SESSION_SECRET=local-test-only-secret-change-before-cloud DEV_LOGIN=1 npm start
```

本地数据保存到 `.local/upgrade.json`，不会写入云数据库。健康检查为 `http://127.0.0.1:8080/healthz`。如使用微信开发者工具联调，在 `minigame/online-config.js` 临时设置 `localUrl: 'ws://127.0.0.1:8080/ws'`，并为各客户端设置不同 `localPlayer`。仅本地工具关闭域名校验；真机不能使用手机自身的127.0.0.1。完成后恢复两个字段为空字符串。四端自动集成测试无需修改配置。

## 2. 开通测试云环境

在当前小游戏账号下开通云开发、云托管，确认套餐费用。先部署测试环境，不上传发布正式版。

在同一云环境创建数据库集合：

- `upgrade_rooms`：房间、服务端私有牌面、租约、已处理请求与结算快照。
- `upgrade_profiles`：可信身份、联机等级、徽章和当前房间。

两个集合的客户端读写权限都设为禁止；只能由服务端通过受信权限访问。不要为排查问题开放客户端读取房间集合，里面保存完整暗牌。无需手工导入玩家数据，新账号自动从2级开始。

## 3. 部署登录云函数

项目已配置 `cloudfunctionRoot: cloudfunctions/`。在开发者工具选择测试云环境，对 `cloudfunctions/login` 执行“上传并部署：云端安装依赖”，选择支持 Node.js 22 或更高兼容运行时。

通过后台环境变量设置 `SESSION_SECRET`：使用密码管理器生成至少32字符的随机密钥。登录云函数与云托管必须使用同一值。密钥仅保存在后台，不填客户端文件、不提交代码、不发送到聊天。

登录云函数从微信上下文获取 APPID/OPENID，不接受客户端指定身份，签发有效期2小时的会话。重连会重新登录。

## 4. 部署云托管服务

从项目根目录的 `Dockerfile` 构建服务，建议服务名 `upgrade-game`。镜像包含服务端与复用的规则文件，不需要上传本地数据或 `.env`。

服务设置：

| 配置 | 值 |
| --- | --- |
| 监听端口 | 8080 |
| 健康检查 | HTTP `/healthz` |
| `STORE` | `cloud` |
| `CLOUD_ENV` | 测试云环境ID |
| `SESSION_SECRET` | 与登录云函数一致的后台密钥 |
| `DEV_LOGIN` | 不设置，禁止值1 |
| 实例最小/最大数量 | 均为1 |

开启 WebSocket 支持，按平台允许范围设置连接时长；连接过期时客户端会重新登录恢复。当前版本必须保持单实例且不缩容到0，确保服务端定时器持续执行。房间有15秒数据库租约防止双写，但尚未实现多实例间房间路由，因此不能直接横向扩容。更新实例后旧租约到期才接管，客户端可能短暂显示恢复中。

给云托管运行身份授予该环境数据库所需的最小权限。SDK需要受信云端凭证：先确认平台是否为服务身份提供SDK可用的临时凭证；若当前环境不提供，按微信云托管/云开发后台文档配置受限服务端凭证，勿放到小游戏或聊天中。本地未配置真实云账号，身份授权、云数据库事务和连接网关仍需部署后验证。

部署完成后修改 `minigame/online-config.js`：`env` 填测试环境ID，`service` 填实际服务名，`localUrl` 与 `localPlayer` 留空。重新编译后点击“好友联机”。默认系统昵称与内置座位头像，不申请微信个人资料或麦克风权限。

## 5. 行为与恢复

四人入座，对家组队，全部准备后由房主开局。发牌中均可叫主，首个有效请求坐庄；无人叫主最后等待15秒，再进入20秒投票，3票同意重发。扣底60秒、出牌30秒、断线30秒后合法托管；每墩展示3秒自动继续。主动离开本局由托管打完并计入成绩，结算释放座位。

服务端提交事务后才广播每人的专属快照；数据库保存完整牌局，重启扫描未结束房间继续推进。请求ID避免重复操作，版本不符返回错误及最新快照。联机成绩与本地练习成绩完全分离，结算时房间和玩家档案在同一事务中写入。

赢家共同选一张互动卡，首个有效确认生效，30秒不确认视为放弃。涂鸦、舞蹈、称号目前以座位标记展示，受影响者自己也能看到；禁言仅为演示标记，没有限制真实麦克风。暂无真实语音、陌生人匹配或主动电脑补位。

## 6. 真机验收清单（尚未执行）

将四个测试微信账号添加为项目成员，至少一台iPhone，通过开发者工具预览测试版本：

1. 创建房间，分享邀请；另一个账号用房间码加入，确认四人座位和对家一致。
2. 两人抢最后座位仅一人成功；重复加入不占新座；旧邀请、满房均有提示。
3. 四人准备开局，验证四人均可叫主，庄家拿33张并扣8张，其余账号看不到底牌或他人手牌。
4. 完整打完一局，核对每墩分数、抠底和升级；双方赢家同时确认互动只产生一次效果。
5. 切后台、断网30秒再恢复，核对托管和手牌不丢失；重复点击不重复出牌。
6. 测试环境牌局中重启服务，等待租约接管，验证四端恢复同一局且未重复结算。
7. 同一微信账号更换设备登录，确认云等级与徽章；原设备连接应失效。
8. 验证房主转移、局中禁止请人、局后请人及新邀请恢复资格。

## 7. 已验证与限制

已验证：本地40项自动化测试通过，包含真实本地WebSocket四客户端整局；JSON持久化重启和事务失败回滚；小游戏界面使用模拟微信API测试。

未验证：真实云环境、云数据库事务/权限、云托管镜像构建和WebSocket网关、微信分享入口、四微信账号与iPhone联调。本机无Docker，未进行容器构建。上述步骤完成后才能标记云端验收通过。

依赖检查：`wx-server-sdk@4.0.2` 的上游传递依赖当前仍有6项 npm audit 告警（5高、1中，涉及旧axios及lodash辅助包）。没有使用强制降级或未经验证的大版本覆盖。发布前需跟进官方修复并复核；当前服务不接受用户指定SDK请求目的地址，也不使用数据库实时watch接口，但不能据此宣称依赖风险已清除。
